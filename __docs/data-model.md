# Data Model — Secure Period Tracking Web App

## Design Decisions

- **Symptom options are stored as reference data**, not hardcoded enums. This allows new options to be added via a seed/migration without altering column types. All selectable values (emotions, discharge types, pain locations, etc.) live in lookup tables.
- **User identity is owned by Keycloak.** The `users` table holds only what the app needs — a stable internal UUID keyed to the Keycloak subject ID (`sub` claim) and user preferences. No passwords, no email storage beyond what Keycloak manages.
- **Sensitive health columns are encrypted at the application layer** (see threat model TS-1, TS-5). Columns marked `[encrypted]` store ciphertext; decryption happens in the Fastify service layer, never in the DB.
- **Row-level ownership.** Every health data table carries a `user_id` foreign key. All queries must include `AND user_id = $authenticatedUserId`.
- **Cycle is the top-level unit.** All logged data belongs to a cycle. A cycle has a start date and an optional end date (set when the next cycle begins or when the user closes it manually).
- **Daily logs are one record per user per day.** A `daily_log` row is the anchor for everything logged on a given date — symptoms, pain, flow, etc. hang off it.
- **Using `node-pg-migrate` for database migrations.** This allows us to version-control our schema changes and seed data in a structured way, with up/down functions for each migration.

### `daily_log_sex`
Single encrypted payload per daily log. Stores the full set of selected sex/intimacy option IDs as AES-256-GCM encrypted JSON.
 
| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK | |
| `daily_log_id` | `uuid` FK → `daily_logs.id` NOT NULL UNIQUE | One row per daily log — UNIQUE enforced |
| `user_id` | `uuid` FK → `users.id` NOT NULL | For RLS |
| `encrypted_payload` | `text` NOT NULL | AES-256-GCM encrypted JSON array of option ID strings. Format: `base64(iv):base64(ciphertext):base64(authTag)` |
| `created_at` | `timestamptz` NOT NULL | |
| `updated_at` | `timestamptz` NOT NULL | |
 
**No FK to `ref_symptom_options`.** The option IDs inside `encrypted_payload` are validated at the service layer before encryption — the service looks up valid option IDs from the `sex` category in `ref_symptom_options` and rejects any unknown IDs before encrypting. Referential integrity is enforced in application code, not at the DB layer.
 
**`UNIQUE (daily_log_id)`** — enforced via the `UNIQUE` constraint on `daily_log_id`. Unlike other multi-select tables that have one row per option, this table has exactly one row per daily log regardless of how many options are selected.

## Analytics — Derived Queries (Not Stored)

These features are computed at query time, not persisted as separate tables.

| Feature | Source tables | Computation |
|---|---|---|
| Average cycle length | `cycles` | `AVG(end_date - start_date)` across closed cycles per user |
| Cycle variation | `cycles` | `STDDEV(end_date - start_date)` over last 6 months per user |
| Average period length | `daily_logs` + `daily_log_flow` | Count distinct `log_date` values where a flow log exists, grouped by cycle |
| Period length chart | `cycles` + above | One data point per cycle: cycle start date + bleeding day count |
| Ovulation prediction | `cycles` | Estimated as `cycle_start + (avg_cycle_length - 14)` days |
| Sleep predictions | `daily_logs` + `daily_log_sleep` | Aggregate sleep option frequency by cycle phase (derived from cycle day number) |

## Notes on Keycloak Integration

- On first login, the Fastify auth middleware reads the `sub` claim from the validated JWT and upserts a row in `users` (`INSERT ... ON CONFLICT (keycloak_sub) DO NOTHING`).
- The app never stores passwords, email addresses, or usernames — those live in Keycloak only.
- When a user deletes their account: delete all rows in all health tables where `user_id = $id`, then delete the `users` row, then call the Keycloak Admin API to delete the identity. This order matters — foreign key constraints will reject deleting the `users` row while child records exist.
